# پلتفرم فروشگاه‌ساز (SaaS)

یک Worker و یک دیتابیس روی **حساب Cloudflare شما**، و به تعداد نامحدود فروشگاه که هر کدام ربات تلگرام خودشان را دارند.
فروشنده‌ها **هیچ حساب Cloudflare یا GitHub لازم ندارند**. فقط در ربات پلتفرم شما توکن ربات‌شان را می‌فرستند و ماهانه اشتراک می‌پردازند.

> نسخه‌ی قبلی (تک‌فروشگاهی) در شاخه‌ی `backup/single-shop-version` محفوظ است.

## چطور کار می‌کند

```
                  ┌──────────────── Worker شما (یک عدد) ────────────────┐
 فروشنده ─────▶  /platform        ربات پلتفرم: ساخت فروشگاه، تمدید، پنل شما
 مشتری‌های A ─▶  /webhook/2       ربات فروشگاه A
 مشتری‌های B ─▶  /webhook/3       ربات فروشگاه B
 مشتری‌های شما ▶ /webhook         فروشگاه خود شما (shop 1، مثل قبل)
                  └──────────── یک دیتابیس D1: همه‌ی جدول‌ها با shop_id ────────────┘
```

### مسیر فروشنده
1. فروشنده ربات پلتفرم شما را باز می‌کند (مثلاً `@YourShopBuilderBot`) و «➕ ساخت فروشگاه» را می‌زند.
2. در @BotFather با `/newbot` یک ربات می‌سازد و **توکن** آن را برای ربات پلتفرم می‌فرستد.
   - پیام حاوی توکن فوراً از چت پاک می‌شود.
   - توکن رمزنگاری‌شده (AES-GCM با `MASTER_KEY`) در دیتابیس ذخیره می‌شود.
3. فروشگاه ساخته می‌شود و **۷ روز رایگان** دارد. فروشنده در ربات خودش `/start` می‌زند و چون مالک است، مستقیم پنل مدیریت را می‌بیند.
4. قبل از پایان دوره، ربات پلتفرم به او یادآوری می‌کند:
   - ۳ روز مانده به پایان
   - روز پایان
   - وقتی فروشگاه بسته می‌شود
5. **تمدید:** ۱، ۳ یا ۶ ماه را انتخاب می‌کند، کارت‌به‌کارت می‌کند و عکس رسید را می‌فرستد. شما در ربات پلتفرم «✅ تایید» را می‌زنید و اشتراک فوراً تمدید می‌شود.
6. **اگر تمدید نکند:** ۳ روز مهلت دارد. بعد فروشگاه **برای مشتری‌ها بسته** می‌شود، ولی ادمین همچنان وارد پنل می‌شود. هیچ داده‌ای پاک نمی‌شود و با تمدید، فوراً باز می‌شود.

### پنل شما (مدیر پلتفرم) در ربات پلتفرم
- **💳 پرداخت‌ها:** رسیدهای منتظر بررسی، با عکس و دکمه‌ی تایید/رد. زدن دوباره‌ی تایید، اشتراک را دو بار تمدید نمی‌کند.
- **🏪 فروشگاه‌ها:** وضعیت همه‌ی فروشگاه‌ها، دادن «۳۰ روز رایگان»، و توقف یا فعال‌سازی یک فروشگاه.
- **📊 درآمد:** درآمد ماه و کل، و تعداد فروشگاه‌های پولی، آزمایشی و منقضی.
- **⚙️ تنظیمات:** قیمت ماهانه (پیش‌فرض **۴۹٬۰۰۰ تومان**)، روزهای آزمایشی، شماره کارت و آیدی پشتیبانی.

## راه‌اندازی (فقط یک بار، توسط شما)

1. در @BotFather یک ربات برای **پلتفرم** بسازید (مثلاً `YourShopBuilderBot`) و توکنش را نگه دارید.
2. یک `MASTER_KEY` تصادفی بسازید؛ مثلاً با `openssl rand -hex 32`، یا بگذارید `npm run deploy` برایتان بسازد.
   ⚠️ **این کلید را جایی امن نگه دارید و هرگز عوضش نکنید.** توکن همه‌ی فروشنده‌ها با آن رمزنگاری شده و با عوض شدنش همه‌ی فروشگاه‌ها قطع می‌شوند.
3. در GitHub بروید به **Settings ← Secrets and variables ← Actions**:

   | نوع | نام | مقدار |
   |---|---|---|
   | Secret | `CLOUDFLARE_API_TOKEN` | توکن Cloudflare (قالب *Edit Cloudflare Workers* + `D1 · Edit`) |
   | Secret | `CLOUDFLARE_ACCOUNT_ID` | Account ID |
   | Secret | `PLATFORM_BOT_TOKEN` | توکن ربات پلتفرم |
   | Secret | `MASTER_KEY` | همان کلید مرحله‌ی ۲ |
   | Variable | `PLATFORM_ADMIN_IDS` | آیدی عددی خودتان، مثلاً `2020715168` |
   | Secret *(اختیاری)* | `BOT_TOKEN` و `WEBHOOK_SECRET` | ربات فروشگاه خود شما (فروشگاه آیلتس) |
   | Variable *(اختیاری)* | `ADMIN_CHAT_IDS` | آیدی عددی شما برای فروشگاه خودتان |

4. **Actions ← Cloudflare Worker ← Run workflow** (یا push روی `master`).
5. آدرس Worker را یک بار در مرورگر باز کنید. هر دو ربات وصل می‌شوند و صفحه وضعیت‌شان را نشان می‌دهد.
6. در ربات پلتفرم `/start` بزنید، بروید به **🔐 پنل مدیریت پلتفرم ← ⚙️ تنظیمات** و شماره کارت و آیدی پشتیبانی را وارد کنید.
7. لینک ربات پلتفرم را برای فروشنده‌ها بفرستید.

داده‌های فروشگاه فعلی شما خودکار **فروشگاه شماره‌ی ۱** می‌شود. همان ربات، همان محصولات، همان مشتری‌ها و بدون اشتراک.

## محدودیت‌ها

### پلن رایگان Cloudflare (کل پلتفرم، همه‌ی فروشگاه‌ها با هم)

| منبع | سقف رایگان | در عمل |
|---|---|---|
| درخواست Worker | ۱۰۰٬۰۰۰ در روز | هر پیام یا دکمه‌ی تلگرام، در هر فروشگاه، یک درخواست است |
| زمان CPU | ۱۰ میلی‌ثانیه برای هر درخواست | کافی است؛ پردازش هر پیام چند میلی‌ثانیه طول می‌کشد |
| درخواست بیرونی | ۵۰ در هر اجرا | هر پیام حداکثر ۵ تا ۶ درخواست؛ یادآوری‌ها در دسته‌های ۴۰تایی |
| **نوشتن در D1** | **۱۰۰٬۰۰۰ ردیف در روز** | **گلوگاه اصلی.** هر کار مشتری حدود ۳ تا ۶ ردیف می‌نویسد |
| خواندن از D1 | ۵ میلیون ردیف در روز | معمولاً مشکلی نیست |
| حجم D1 | ۵ گیگابایت | برای میلیون‌ها محصول و سفارش کافی است |

⚠️ از سپتامبر ۲۰۲۶ Cloudflare سقف D1 رایگان را **سخت‌گیرانه اجرا می‌کند**. وقتی به سقف روزانه برسید، تا ساعت ۰۰:۰۰ UTC (۳:۳۰ بامداد تهران) **همه‌ی فروشگاه‌ها از کار می‌افتند**.

**تخمین:** پلن رایگان برای کل پلتفرم حدود **۱۵ تا ۲۵ هزار پیام و کلیک مشتری در روز** جا دارد. مثلاً ۳۰ فروشگاه با هر کدام حدود ۵۰۰ تعامل در روز.
وقتی به این حد نزدیک شدید، **Workers Paid (ماهی ۵ دلار)** را فعال کنید. این پلن ۱۰ میلیون درخواست و ۵۰ میلیون نوشتن در D1 در ماه دارد؛ یعنی چند صد فروشگاه. درآمد اشتراک چند فروشنده این هزینه را پوشش می‌دهد.
مصرف را در داشبورد Cloudflare، بخش **D1 ← Metrics**، ببینید.

### سقف هر فروشگاه (`src/limits.ts` → `PLAN_LIMITS`)

| مورد | سقف |
|---|---|
| محصول | ۳۰۰ |
| دسته‌بندی | ۳۰ |
| سوال متداول | ۵۰ |
| ادمین اضافه (غیر از مالک) | ۳ |
| فروشگاه برای هر فروشنده | ۳ (`MAX_SHOPS_PER_SELLER` در `src/platform.ts`) |
| مشتری، سفارش، عکس | **نامحدود** |

فروشگاه خود شما (shop 1) هیچ سقفی ندارد.

### عکس‌ها
عکس محصول و رسید **روی سرورهای تلگرام** نگه داشته می‌شود و ربات فقط شناسه‌ی آن (`file_id`) را ذخیره می‌کند. پس فضای شما مصرف نمی‌شود و تعداد عکس محدودیتی ندارد.
محدودیت‌های خود تلگرام این‌هاست: عکسی که کاربر می‌فرستد حداکثر ۱۰ مگابایت، و فایلی که ربات دریافت می‌کند حداکثر ۲۰ مگابایت.

## پرداخت: چرا کارت‌به‌کارت؟

درگاه‌های ایرانی (زرین‌پال، زیبال، …) معمولاً درخواست‌ها را فقط از سرورهای داخل ایران قبول می‌کنند و نماد اعتماد می‌خواهند. Worker روی سرورهای خارج از ایران اجرا می‌شود.
برای همین پرداخت فعلاً کارت‌به‌کارت با رسید و تایید شما انجام می‌شود؛ همان روشی که خود فروشگاه‌ها هم دارند.
برای درگاه، کد پرداخت در یک جا جمع شده است (`receiveReceipt` و `payments.approve` در `src/platform.ts`). اگر بعداً یک سرور واسط داخل ایران داشتید، می‌شود درگاه را اضافه کرد.

## امنیت

| خطر | محافظت |
|---|---|
| دیدن یا تغییر داده‌ی فروشگاه دیگر | **همه‌ی** کوئری‌ها `shop_id = ?1` دارند؛ کوئری بدون آن اصلاً اجرا نمی‌شود. تست‌ها نشان می‌دهند حتی با id جعلی، فروشگاه ۲ به داده‌ی فروشگاه ۱ نمی‌رسد |
| دکمه‌ی جعلی برای فروشگاه دیگران در ربات پلتفرم | هر عملیات، مالک بودن فروشگاه را سمت سرور بررسی می‌کند |
| نشت دیتابیس | توکن ربات فروشنده‌ها با `MASTER_KEY` رمزنگاری شده است |
| وبهوک جعلی | هر فروشگاه secret تصادفی خودش را دارد؛ secret ربات پلتفرم از `MASTER_KEY` مشتق می‌شود |
| دو بار تایید یک پرداخت | تایید و تمدید در یک تراکنش و فقط برای پرداختِ «منتظر» انجام می‌شود |
| یک رسید برای چند تمدید | رسید تکراری رد می‌شود (`receipt_unique_id` یکتاست) و هر فروشگاه فقط یک پرداخت منتظر می‌تواند داشته باشد |
| اسپم | محدودیت ارسال پیام برای هر چت، پردازش هر update فقط یک بار، و سقف منابع هر فروشگاه |

## فایل‌های مرتبط

```
migrations/0004_multi_tenant.sql   جدول shops و subscription_payments، و shop_id در همه‌ی جدول‌ها
src/platform.ts                    ربات پلتفرم: ساخت فروشگاه، تمدید، پنل شما، یادآوری cron
src/views/platform.ts              صفحه‌های ربات پلتفرم
src/tenancy.ts                     پیدا کردن فروشگاه از روی آدرس وبهوک و بررسی secret
src/crypto.ts                      رمزنگاری توکن‌ها، secretهای مشتق‌شده، مقایسه‌ی امن
src/services/subscription.ts       قوانین اشتراک: فعال، مهلت، بسته، یادآوری
src/db/platform.ts                 جدول‌های پلتفرم (فروشگاه‌ها و پرداخت‌ها)
test/platform.e2e.test.ts          سناریوی کامل پلتفرم با Worker واقعی
```
